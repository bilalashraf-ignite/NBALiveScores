Create hook to detect cellular vs WiFi/ethernet connections using Network Information API:

1. Create useNetworkType hook (src/hooks/useNetworkType.ts):
   ```tsx
   import { useState, useEffect } from 'react';

   /**
    * Hook to detect network connection type for adaptive behavior.
    * Uses Network Information API (Chrome, Edge, Samsung Internet only as of 2026).
    * Gracefully degrades to '4g' assumption on unsupported browsers.
    *
    * Returns: 'slow-2g' | '2g' | '3g' | '4g' | 'unknown'
    */
   export function useNetworkType() {
     const [effectiveType, setEffectiveType] = useState<string>('4g');
     const [isSupported, setIsSupported] = useState<boolean>(false);

     useEffect(() => {
       // Type assertion for Network Information API
       const connection = (navigator as any).connection || (navigator as any).mozConnection || (navigator as any).webkitConnection;

       if (!connection) {
         // Unsupported browser (Safari, Firefox)
         setIsSupported(false);
         setEffectiveType('4g'); // Assume fast connection
         return;
       }

       setIsSupported(true);

       const updateType = () => {
         setEffectiveType(connection.effectiveType || '4g');
       };

       // Set initial value
       updateType();

       // Listen for changes (WiFi ↔ cellular transitions)
       connection.addEventListener('change', updateType);

       return () => {
         connection.removeEventListener('change', updateType);
       };
     }, []);

     return { effectiveType, isSupported };
   }
   ```

2. Add JSDoc comments explaining:
   - Browser support (Chrome/Edge/Samsung only)
   - Fallback behavior (assumes 4g on unsupported)
   - Event listener for network changes
   - Return values: slow-2g, 2g, 3g, 4g

Why Network Information API: Only browser API that detects cellular vs WiFi
Why default to '4g': Optimistic assumption for unsupported browsers (Safari, Firefox)
Why listen for 'change': Detects transitions (e.g., user leaves WiFi, switches to cellular)

Browser support note: ~70% global coverage (Chrome/Edge dominant on mobile). Safari/Firefox users get default 10s frequency.

3. Add frequency calculation inside useSSE function (after options destructuring):
   ```tsx
   export function useSSE<T>(options: UseSSEOptions): UseSSEReturn<T> {
     const { url, enabled = true, adaptiveFrequency = false } = options;

     const { effectiveType } = useNetworkType();

     // Calculate update frequency based on network
     const frequency = useMemo(() => {
       if (!adaptiveFrequency) return 10000; // Default 10s

       // Cellular (2G/3G): 20s (50% reduction)
       if (['slow-2g', '2g', '3g'].includes(effectiveType)) {
         return 20000;
       }

       // WiFi/4G: 10s
       return 10000;
     }, [adaptiveFrequency, effectiveType]);
   ```

   ```

5. Update server endpoint to respect frequency parameter:

   - Change to read from query param: `const frequency = parseInt(searchParams.get('frequency') || '15000')`
   - Use frequency variable in setTimeout instead of hardcoded 15000
   - Clamp to safe range: `Math.max(5000, Math.min(frequency, 60000))` (5s-60s)

6. Add comment explaining cellular detection:

   /**
    * Adaptive frequency reduces bandwidth on cellular connections:
    * - WiFi/4G: 10 second updates (baseline)
    * - 2G/3G: 20 second updates (50% reduction)
    * - Detects network changes and adjusts immediately
    */
   ```

Why 50% reduction: Balances data savings with score freshness (20s still feels real-time for sports)
Why query param: Server-driven polling interval, client controls based on network
Why clamp 5s-60s: Prevents abuse (too fast) or staleness (too slow)
