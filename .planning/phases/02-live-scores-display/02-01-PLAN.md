  - Fetches live NBA games using `adapter.getLiveGames('nba')` from Phase 1

  - On cache miss or stale data, fetches from adapter and updates cache with `cache.set(cache.keys.liveGames('nba'), games, CACHE_TTL.LIVE_GAME)`

  - Loops indefinitely while connection is open

  - Cache-Control: no-cache
  - Connection: keep-alive

- Use balldontlie adapter from Phase 1: `import { adapter } from '@/lib/adapters'`
- SSE data format MUST be: `data: <json>\n\n` (two newlines required)
- Do NOT use WebSockets (overkill for unidirectional updates)
- Stream runs indefinitely until client disconnects

  <name>Task 2: Create custom React hook for SSE connection management</name>
  <files>src/hooks/useSSE.ts, tests/hooks/useSSE.test.tsx</files>
  <action>
Create reusable React hook that manages EventSource lifecycle with proper cleanup.

**Implementation:**
- Define TypeScript interfaces:
  ```typescript
  interface UseSSEOptions { url: string; enabled?: boolean; }
  interface UseSSEReturn<T> { data: T | null; isConnected: boolean; error: Error | null; reconnect: () => void; }
  ```
- Hook state: `data`, `isConnected`, `error` via useState; `eventSourceRef` via useRef
- `connect()` function (useCallback):
  - Check `options.enabled` (default true)
  - Create new EventSource with options.url
  - Store in eventSourceRef.current
  - Set up event handlers:
    - `onopen`: Set isConnected=true, error=null
    - `onmessage`: Parse JSON from event.data, update data state, catch parse errors
    - `onerror`: Set isConnected=false, error with message "SSE connection failed"
- useEffect with connect() and CRITICAL cleanup:
  ```typescript
  return () => {
    eventSourceRef.current?.close();
    eventSourceRef.current = null;
  };
  ```
- `reconnect()` function: Close existing connection, call connect()
- Return object with data, isConnected, error, reconnect

**Test file (tests/hooks/useSSE.test.tsx):**
- Test connection lifecycle: opens, receives data, closes on unmount
- Test error handling: onerror sets error state
- Test reconnect function: closes old connection, opens new one
- Test cleanup: verifies EventSource.close() called on unmount
- Use React Testing Library renderHook, mock EventSource global

**Why this matters:** Missing cleanup causes memory leaks (RESEARCH.md Pitfall 1). EventSource connections persist after unmount, accumulating until browser crashes.

**Pattern source:** RESEARCH.md Pattern 2 - verified against OneUptime guide (Jan 2026)

  <action>
Create API route for manual score refresh triggered by user action (LIVE-08 requirement).

**Implementation:**
- Export POST handler (not GET - user action, not idempotent read)
- Extract league from request body: `const { league } = await request.json()`
- Default to 'nba' if not provided
- Fetch fresh data from adapter: `const games = await adapter.getLiveGames(league)`
- Clear stale cache: `await cache.del(cache.keys.liveGames(league))`
- Update with fresh data: `await cache.set(cache.keys.liveGames(league), games, CACHE_TTL.LIVE_GAME)`
- Return JSON response: `{ success: true, games, timestamp: new Date().toISOString() }`
- Wrap in try/catch, return 500 with error message on failure

**Why POST not GET:** User-initiated refresh is an action with side effects (cache invalidation). GET should be idempotent per HTTP semantics.

**Error handling:** If adapter fails, return cached data if available, otherwise return error with helpful message: "Unable to refresh scores. Please try again."
